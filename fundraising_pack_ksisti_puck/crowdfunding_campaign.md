**Help Ksisti-Puck LLC Upgrade the Workbench for Four Independent Software Platforms**

## Short Campaign Pitch

Ksisti-Puck LLC has built four early software platforms with working code, product boundaries, and real starter architecture: Entangled Oracle, Shadow Compass, ChartTrace ScribeShield, and FlareFrame MG Signal.

The immediate bottleneck is not imagination. It is operations: a small, low-RAM laptop, unstable working conditions, and limited access to the software subscriptions needed to refine, test, document, and package these products with production-level control.

This campaign funds a practical upgrade: a refurbished desktop, a thrifted desk, and several months of baseline software/tooling subscriptions so the existing codebases can be stabilized, documented, tested, and moved toward clearer demos, pilots, and release candidates.

## Main Campaign Page

Ksisti-Puck LLC is a small independent software studio building four starter platforms:

**Entangled Oracle** is a local-first astrology and symbolic report engine with Android and dashboard companions. It focuses on inspectable calculations, structured report generation, authored interpretation blocks, and provenance-aware symbolic tools.

**Shadow Compass** is a guided reflection and emotional-regulation platform. It is designed around consent, user-owned pattern review, privacy boundaries, and cautious AI-assisted workflows.

**ChartTrace ScribeShield** is a documentation-integrity tool for reviewing AI-generated clinical notes against clinician-authorized source packets before signature. Its v0.1 prototype includes synthetic cases, risk scoring, review workflow, and export packets.

**FlareFrame MG Signal** is a Myasthenia Gravis-focused Android companion for symptom, flare, treatment, recovery, function, and appointment-summary tracking. Its current build is local-first and designed not to fabricate missing data.

These are not vague ideas. They already exist as codebases, prototypes, docs, contracts, and working starter systems. What they need now is a stable production workbench.

## Why This Campaign Exists

The current operating setup is a small, glitchy, low-RAM laptop. That makes every serious development task harder:

- Android builds stall or time out.
- Local servers compete for memory.
- Browser testing is unstable.
- Documentation, design, and code review workflows are slow.
- Multi-repo consolidation is harder than it needs to be.
- Production polish suffers because the machine cannot comfortably run the stack.

The goal is deliberately practical: upgrade the workstation, establish a basic physical work area, and cover the software subscriptions needed to refine the existing platforms.

## What Funding Unlocks

Funding will support:

- A refurbished desktop with enough RAM for Android Studio, local servers, browsers, test runners, and documentation tools.
- A thrifted desk or basic workstation setup.
- External storage and backup safety.
- Several months of software subscriptions for development, design, AI-assisted coding/review, hosting, source control, documentation, and testing.
- Time and stability to improve product demos, validation packets, onboarding, documentation, and packaging.

## What Supporters Are Actually Funding

Supporters are funding operational capacity, not a promise of instant commercial success.

The near-term deliverables are:

- Cleaner demos for the four starter platforms.
- Better documentation and product pages.
- More stable test/build workflows.
- Product roadmaps that distinguish implemented features from planned features.
- Improved investor/customer-facing materials.
- More disciplined packaging for pilots, beta testers, and early adopters.

## Public Boundaries

- that any product is clinically validated;
- that any product replaces medical care, therapy, professional judgment, or crisis support;
- that astrology or symbolic tools are scientific prediction systems;
- that investors or supporters will receive financial returns;
- that current prototypes are finished commercial products.

The campaign does claim:

- working starter platforms exist;
- the studio needs better operating infrastructure;
- better equipment and subscriptions will directly improve development throughput;
- supporters can help turn rough-but-real software into better packaged demos and pilots.
